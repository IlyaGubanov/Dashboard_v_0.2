# Расчёт показателей (этап 4)

Код: [apps/api/src/kpi](../apps/api/src/kpi) — `engine.ts` (правила), `metrics.ts` (библиотека доп. показателей),
`loader.ts` (загрузка из БД), `kpi.service.ts` (срезы, кэш, права). Тест: `engine.spec.ts`.

Раньше каждый из четырёх модулей считал по-своему, в своём коде. Теперь правила **одни**, а различия направлений
задаются настройками направления в БД: `progress_method`, `plan_method`, `money_source`, `plan_weekday`, пороги, `settings.kpis`.

## API

| Запрос | Что отдаёт |
|---|---|
| `GET /api/overview` | производственная сводка: все доступные пользователю направления с показателями на последнюю отчётную точку |
| `GET /api/directions/:code/kpi?date=ГГГГ-ММ-ДД` | показатели направления; с `date` — срез на прошлую дату (последняя отчётная точка не позже даты) |
| `GET /api/directions/:code/sites?date=…` | реестр объектов: готовность, план, отклонение, состояние, деньги, люди, техника, кураторы |
| `GET /api/directions/:code/periods` | отчётные точки (новые сверху) и их статус: открыта / закрыта куратором / заблокирована |

Права те же, что у направлений: сотрудник видит только свои направления, руководство и администратор — все.
Результат кэшируется на 60 секунд; при записи данных (этап 7) кэш направления будет сбрасываться сразу.

## Правила

| Что | Правило |
|---|---|
| Факт позиции | КС-2 подписаны / оплачено → 100 %; «исключено» → не участвует; есть проектный и фактический объём → min(1, факт / проект); иначе — % готовности |
| Какая запись берётся | недели и дни — последняя запись не позже отчётной точки (если на этой неделе позицию не обновляли, действует прошлое значение); отчёты — запись этого отчёта |
| План позиции / объекта | линейно от начала до окончания на дату плана: неделя — **среда** (`plan_weekday = 3`), день и отчёт — сама дата |
| Готовность объекта | среднее по позициям с весом: стоимость (МКД), объём при одной единице измерения (Сети), вес вида работ (Школы) |
| Готовность направления | МКД — по всем позициям, взвешенно по стоимости; Сети — по объектам, взвешенно по сумме договоров; Школы — среднее по школам; Благоустройство — доля позиций с выполненным проектным объёмом |
| Состояние объекта | выполнено (≥ 99,5 %) → не начато по графику (план и факт < 0,5 %) → критично (отставание хуже `thr_crit`) → отставание (хуже `thr_warn` или есть просроченные позиции) → в графике |
| Светофор направления в сводке | отклонение факт − план хуже −2 п.п. — отставание, хуже −10 п.п. — критично (`app_setting['overview.thresholds']`) |
| «Не проверено» | `verified = false`, если отчётная точка ещё открыта (куратор её не закрыл) |
| Динамика | `prev` — показатели предыдущей отчётной точки (если за неё есть данные) |

## Проверка

`npx vitest run src/kpi` (нужна БД с демо-данными). При датах плана исходных модулей (МКД — пятница, Сети — понедельник,
Школы — 27.10.2026) движок даёт **те же** показатели, что старый дашборд: готовность, план, отстающие и критичные,
люди, техника, деньги, список «Наибольшее отставание» в том же порядке, все 12 доп. показателей, замечания. 8 из 8 тестов.

## Что изменилось по сравнению со старым дашбордом (по решениям заказчика)

| Направление | Дата плана | План | Отстают | Критично |
|---|---|---|---|---|
| МКД | пятница 30.10 → **среда 28.10** | 90,3 % → 89,7 % | 19 → 18 | 5 → 4 |
| Сети | понедельник 26.10 → **среда 28.10** | 37,3 % → 38,3 % | 35 → 38 | 16 → 19 |
| Школы | «сегодня» (27.10) → **дата данных 23.10** | 34,8 % → 33,8 % | 4 → 4 | 4 → 3 |
| Благоустройство | графика нет | — | — | — |

Школы: старый модуль сравнивал факт на дату выгрузки с планом на день открытия страницы, поэтому отставание
росло само по себе, пока данные не обновляли. Теперь факт и план берутся на одну дату.

## Доп. показатели направления

Набор задаётся в `direction.settings.kpis` (сид записывает исходные наборы; правки не затираются):

```json
[{ "metric": "toPay", "label": "К оплате (КС-2 подписаны)" },
 { "metric": "itemsByStatus", "label": "Позиций в работе", "params": { "statuses": ["work", "stop"] } }]
```

| Метрика | Что считает | Параметры |
|---|---|---|
| `toPay` | принято по КС-2, но не оплачено | — |
| `overdueItems` | позиций с истёкшим сроком, не выполненных | — |
| `itemsByStatus` | позиций в статусах | `statuses` |
| `qtyByUnit` | сумма фактических объёмов в единице | `unit` |
| `sitesDone` | выполненных объектов (из N) | — |
| `advance` | аванс по договорам | — |
| `scheduleLagDays` | отставание в днях: сколько дней назад план был равен текущему факту | — |
| `trackerOverdue` | строк надстройки с прошедшей плановой датой и незавершённым этапом | `tracker`, `stage` |
| `trackerStatusDone` | объектов, где этап надстройки в итоговом статусе (из N) | `tracker`, `stage` |
| `reportStatusCount` | объектов отчёта со статусом из списка (из N) | `statuses` |
| `sitesWithRemainder` | объектов с невыполненными объёмами, кроме завершённых | `doneStatuses` |
| `remarksTotal` | замечаний в отчёте | — |
| `peopleTotal` | людей на объектах | — |

Новое направление собирает свой набор из этих метрик; новая метрика — одна функция в `metrics.ts`.

## Экран «Производственная сводка» (этап 5)

Код: [apps/web/src/pages/OverviewPage.tsx](../apps/web/src/pages/OverviewPage.tsx), блоки — [pages/overview](../apps/web/src/pages/overview).
Данные — один запрос `GET /api/overview`, обновляется сам раз в 5 минут и по кнопке «Обновить».

| Блок | Что показывает | Чего не было в старом дашборде |
|---|---|---|
| Итоги | объектов, отстают, критично, людей, техники, стоимость работ — по всем направлениям | вся строка новая |
| Карточки направлений | готовность против плана (полоса + метка плана), отклонение, состояние со значком, отстают / критично, люди, техника, 3 ключевых показателя, куратор | изменение к прошлой неделе / отчёту, метки «не проверено» и «демо», подсказка при наведении |
| Таблица | те же цифры строкой на направление | вид для сравнения и экранного диктора |
| Наибольшее отставание | 10 худших объектов по отклонению факт − план, полоса отклонения, состояние | фильтр по направлению |
| Деньги по направлениям | стоимость, закрыто по КС-2, оплачено — одна шкала, подпись у каждой полосы, доля от стоимости в подсказке | — |
| Замечания | объекты Благоустройства с наибольшим числом замечаний и остатком объёмов | — |

Цвета состояний и серий — в [theme.css](../apps/web/src/theme.css); палитра серий проверена на различимость
при нарушениях цветового зрения в светлой и тёмной темах. Состояние всегда показывается значком и подписью, не только цветом.
