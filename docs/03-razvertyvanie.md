# Развёртывание МВС СТ на сервере с доступом из интернета

## Схема

```
Интернет / локальная сеть
        │  443 (HTTPS), 80 (только перенаправление на HTTPS и выпуск сертификата)
        ▼
┌─ caddy ─────────┐  сертификат, HTTPS, заголовки безопасности, /api/docs закрыт
│                 │
└──────┬──────────┘
       ▼
┌─ web (nginx) ───┐  интерфейс, /api → api
└──────┬──────────┘
       ▼
┌─ api (NestJS) ──┐  вход, права, журнал, данные
└──────┬──────────┘
       ▼
┌─ db (MySQL 8.4)─┐  наружу не открыт
└─────────────────┘
```

Наружу открыты только порты 80 и 443 контейнера `caddy`. База, API и nginx доступны только внутри Docker.

## 1. Виртуальная машина в Hyper-V

Docker Desktop официально не поддерживается на Windows Server, поэтому рекомендуется Linux-VM:

1. Hyper-V → «Создать виртуальную машину»: поколение 2, 4 vCPU, 8 ГБ ОЗУ, диск 60 ГБ, внешний виртуальный коммутатор.
2. Установите **Ubuntu Server 24.04 LTS** (в параметрах безопасности VM выберите шаблон «Microsoft UEFI Certificate Authority»).
3. Задайте VM постоянный IP-адрес в локальной сети.
4. Установите Docker:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

5. Включите брандмауэр, оставив SSH и веб:

```bash
sudo ufw allow OpenSSH && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw allow 443/udp && sudo ufw enable
```

## 2. Домен и сеть

1. Выберите адрес, например `dashboard.mvs-st.ru`, и создайте DNS-запись **A** на внешний IP организации.
2. На маршрутизаторе / межсетевом экране пробросьте порты **80** и **443** (TCP, для 443 ещё и UDP) на IP виртуальной машины.
3. Если пользователи из локальной сети открывают тот же адрес, внутренний DNS должен отдавать для него внутренний IP VM
   (или маршрутизатор должен поддерживать NAT loopback).

## 3. Сертификат: какой режим выбрать

| `TLS_MODE` | Когда | Что нужно |
|---|---|---|
| `auto` (рекомендуется) | есть домен и порты 80/443 открыты из интернета | ничего: Caddy сам выпустит бесплатный сертификат Let's Encrypt и будет продлевать его заранее |
| `files` | в организации свой (корпоративный, wildcard) сертификат | положить `cert.pem` (с цепочкой) и `key.pem` в `deploy/certs/`; продлевать вручную до истечения срока |
| `internal` | проверка до настройки домена, доступ только из внутренней сети | ничего; браузер покажет предупреждение о недоверенном сертификате |

## 4. Запуск

Проще всего — скриптом. Он сделает всё по порядку:

- установит Docker, если его нет;
- спросит домен, режим сертификата и нужны ли демо-данные;
- сгенерирует пароли в `.env`;
- соберёт и запустит контейнеры, дождётся ответа API;
- включит ночные резервные копии.

```bash
git clone <репозиторий> mvs-st && cd mvs-st     # или распакуйте архив с кодом
sudo bash deploy/install.sh
docker compose logs -f caddy     # для TLS_MODE=auto дождитесь «certificate obtained successfully»
```

Скрипт выведет логин `admin` и временный пароль. Откройте `https://<DOMAIN>` — при первом входе система попросит сменить пароль.

Вручную — то же самое: `cp .env.example .env`, заполнить `DOMAIN`, `TLS_MODE`, пароли, затем `docker compose up -d --build`.

Дальше — по плану запуска: [10-zapusk.md](10-zapusk.md).

## 5. Что защищает приложение при доступе из интернета

| Мера | Где |
|---|---|
| Только HTTPS, http → https, HSTS (для `auto` и `files`) | caddy |
| Cookie входа `HttpOnly; Secure; SameSite=Lax`, в БД — только хэш токена | api |
| Пароли bcrypt, от 10 символов с буквами и цифрами, смена при первом входе | api |
| Блокировка входа на 15 минут после 5 неудачных попыток; не более 10 попыток в минуту с адреса | api |
| Реальный IP пользователя в журнале (подставной `X-Forwarded-For` отбрасывается) | caddy + api (`TRUST_PROXY_HOPS=2`) |
| Заголовки: CSP, X-Frame-Options, nosniff, Referrer-Policy; сервер не называет себя | caddy |
| Документация API снаружи закрыта | caddy + api (`API_DOCS=false`) |
| MySQL, API и nginx не опубликованы наружу | docker-compose |

## 6. Обслуживание

| Что | Команда | Примечание |
|---|---|---|
| Резервная копия | `sudo bash deploy/backup.sh` | база + фото и документы в `/var/backups/mvs`, хранится 14 дней; по расписанию — каждую ночь в 02:30 (ставит `install.sh`). Каталог и срок — `BACKUP_DIR`, `KEEP_DAYS` |
| Восстановление | `sudo bash deploy/restore.sh db-….sql.gz [files-….tar.gz]` | спросит подтверждение и сначала сохранит текущее состояние |
| Обновление | `sudo bash deploy/update.sh` | копия → `git pull` → пересборка → проверка; миграции базы применяются при старте |
| Журналы | `docker compose logs --tail=200 api` | у каждого контейнера не больше 5 × 10 МБ |
| Состояние | `docker compose ps` | у `db` и `api` должно быть `healthy` |
| Место на диске | `df -h /var/lib/docker /var/backups` | фото копятся в томе `files_data` |

Копии в `/var/backups/mvs` лежат на той же VM и пропадут вместе с ней — **регулярно уносите их на другой диск или сервер**. Том `caddy_data` содержит сертификаты — не удаляйте его, иначе Caddy будет выпускать их заново
(у Let's Encrypt есть лимиты на частоту выпуска).

## 7. Если не открывается

| Признак | Причина |
|---|---|
| В логах caddy ошибка получения сертификата | DNS ещё не указывает на сервер или порт 80 закрыт снаружи |
| Браузер: «соединение не защищено» | режим `internal` или в `files` не хватает промежуточного сертификата в `cert.pem` |
| Вход проходит, но сразу выкидывает на страницу входа | открыто по `http://` при `COOKIE_SECURE=true` — заходите по `https://` |
| `502 Bad Gateway` | контейнер `api` ещё стартует (миграции, демо-данные) — `docker compose logs api` |
