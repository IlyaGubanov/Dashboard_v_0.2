# Первый запуск: одна школа, один регистратор

1. В приватном `.env` указать реальные сети регистратора в `VIDEO_ALLOWED_NETWORKS`. Для внутреннего DNS также указать `VIDEO_ALLOWED_DNS_SUFFIXES`; RTSP-порт по умолчанию 554. Проверить, что внутренняя control-подсеть `172.31.250.0/29` свободна, либо заменить её и согласованный `VIDEO_CONTROL_API_IP`.
2. Подготовить секреты и сохранить их в защищённой резервной копии:
   ```bash
   bash deploy/video-secrets.sh
   docker compose up -d --build
   ```
3. В Dahua создать отдельного пользователя с просмотром нужных каналов. Специалист вручную настраивает дополнительный поток пилотной камеры на обычный H.264: ориентировочно 15 fps, 512–1024 Кбит/с, I-интервал 30. Основной поток записи приложение не меняет.
4. Администратор → «Настройки видеонаблюдения» → «Добавить регистратор»: выбрать школу, ввести действительный локальный адрес, порт и учётную запись просмотра. «Проверить подключение» подтверждает только доступность порта.
5. «Камеры» → «Добавить камеру»: реальный канал 1–16, дополнительный поток. Нажать «Проверить изображение». Дождаться состояния синхронизации «Применено».
6. Открыть школу → «Камеры». Проверить прямой эфир на компьютере и телефоне. Убедиться, что после закрытия просмотра источник отключается, а DMSS и запись регистратора работают штатно.
7. Для сотрудников выдать явные права на эту школу в карточке сотрудника → «Камеры». Просмотр и управление назначаются отдельно. Затем подключать оставшиеся каналы и школы через интерфейс.

Отчётная дата карточки не меняет видео: это всегда прямой эфир. H.265 не гарантирует совместимость со всеми браузерами. Реальные IP и пароли после установки вводит администратор.
