# МВС СТ — производственный дашборд

Корпоративное приложение вместо HTML-дашборда: сводка руководства по направлениям (Школы, МКД, Сети, Благоустройство),
еженедельный ввод факта ответственными, кураторы, замечания с фото, журнал изменений. ~200 пользователей, доступ из интернета.

Пользователь — русскоязычный, не разработчик: отвечать по-русски, без жаргона; интерфейс, комментарии в коде,
сообщения об ошибках и документация — на русском.

## Стек и структура

Монорепозиторий npm workspaces, Node.js 22+.

| Папка | Что | Технологии |
|---|---|---|
| `packages/shared` | zod-схемы и типы, общие для сервера и интерфейса | zod 4, tsup (ESM + CJS) |
| `apps/api` | сервер | NestJS 11, Prisma 6, MySQL 8 |
| `apps/web` | интерфейс | React 19, Vite 7, Mantine 8, TanStack Router + Query; ECharts и OpenLayers грузятся лениво |
| `deploy/` | сервер: HTTPS-шлюз Caddy, `install.sh`, `backup.sh`, `restore.sh`, `update.sh` | Docker Compose |
| `scripts/local.ps1`, `local.cmd` | запуск на Windows без Docker | PowerShell 5.1 |
| `docs/` | всё описание по этапам: `01`…`13` | |

Ключевые места:
- `apps/api/prisma/schema.prisma` — схема; `prisma/migrations/` — миграции; `prisma/seed.ts` — справочники (идемпотентно);
  `prisma/demo/` — демо-данные исходного дашборда, сверка (`verify.ts`, `kpi_reference.json`), демо-учётки (`users.ts`).
- `apps/api/src/kpi/` — расчёт показателей: `engine.ts` (чистые функции), `metrics.ts` (библиотека плиток сводки),
  `forecast.ts`, `loader.ts`; кеш 60 с, `kpi.invalidate(directionId)` после любой записи.
- `apps/api/src/auth/access.service.ts` — все правила доступа (кто видит, кто вносит, кто управляет).
- `apps/api/src/entry/` ввод факта и журнал, `manage/` объекты и справочники, `admin/` конструктор направлений,
  `remarks/` замечания, `attachments/` файлы, `tasks/` «Мои задачи», `users/` пользователи и загрузка списком,
  `appearance/` оформление (цвета, шрифт, название — настраивает администратор, см. `docs/13-oformlenie.md`).
- `apps/web/src/api.ts` — запросы (`directionQueries`), `router.tsx` — маршруты, `pages/direction/` — вкладки направления,
  `pages/direction/search.ts` — параметры адреса (`tab`, `date`, `site`, `remark`…), `theme.css` — цвета, `ui/` — общие компоненты.

## Команды

```bash
npm ci
npm run build -w @mvs/shared          # после любой правки packages/shared — иначе сервер и интерфейс видят старые типы
npm run db:generate                    # после правки schema.prisma (остановите запущенный API: Windows держит DLL)
cd apps/web && npx tsc --noEmit -p .   # типы интерфейса
cd apps/api && npx tsc --noEmit -p tsconfig.json && npx tsc --noEmit -p prisma/tsconfig.json
cd apps/api && npx vitest run          # тесты расчёта
npm run build -w @mvs/web              # полная сборка интерфейса
```

Локальный запуск: `local.cmd setup` (один раз), `local.cmd start` → http://localhost:5173.
Учётки: `admin` / пароль из `local.env`, `rukovod` / `Rukovod2026demo`, `kurator` / `Kurator2026demo`, `vvod` / `Vvod2026demo`.
API вручную: в `apps/api` с переменными `DATABASE_URL`, `COOKIE_SECURE=false`, затем `node dist/main.js` (после `npm run build -w @mvs/api`).
Превью в приложении Claude — конфигурация `web` в `.claude/launch.json` (нужен запущенный API на :3000).

`engine.spec.ts` сверяет расчёт с исходным дашбордом и проходит только на **чистых** демо-данных:
после ручного ввода — `local.cmd demo` или `npx tsx prisma/demo/import.ts --force --delete-manual-data`.

## Модель и принятые решения (не переспрашивать)

- Одна модель для всех направлений: направление → объекты → позиции (виды работ) → факт по отчётным точкам.
  Различия направлений — в настройках (`progressMethod`, `planMethod`, `moneySource`, статусы, доп. поля, надстройки,
  плитки сводки), а не в коде. Новое направление собирается в «Конструкторе направлений».
- Вход — свой логин и пароль (не AD). Пароль от 10 символов, буквы и цифры; блокировка на 15 минут после 5 ошибок;
  смена при первом входе. Сессия — cookie `mvs_sid`, в базе только хэш.
- Роли: глобальные ADMIN / MANAGEMENT / USER; в направлении CURATOR / EDITOR / VIEWER; у ответственного за ввод
  область — всё направление, лоты (SECTIONS) или назначенные объекты (SITES). Ответственных назначает администратор.
- Поверх ролей — галочки в карточке сотрудника: скрытые разделы (`APP_SECTIONS`) и отключённые возможности (`FEATURES`:
  финансы, создание замечаний, выгрузка, журнал). Только сужают права, на администратора не действуют; проверяются
  и сервером (`AccessService.canSee/has`, `kpi/finance.ts`), и интерфейсом (`ui/access.ts`). Подразделения — общий справочник.
- План недели считается **на среду** (`planWeekday = 3`). Пороги отставания — как в исходном дашборде: у объектов —
  в настройках направления (конструктор), у направлений в сводке — −2 / −10 п.п.
- Подрядчики — свой справочник в каждом направлении.
- **Удаление = архив** (объекты, позиции, поля, файлы). Насовсем — только администратор, и только то, на что нет ссылок.
- Неделя: OPEN → CLOSED (куратор проверил) → LOCKED (администратор). Сводка показывает и непроверенное — с пометкой.
- Каждое изменение — в журнал (`AuditService`, до/после). Одновременная правка — поле `version`, при конфликте 409.
- Замечания: Открыто → В работе → Устранено → Принято / Снято; номер в направлении; лента событий с фото.
- Демо-данные: после `--clear` направление помечается и при перезапуске демо в него не возвращается.

## Правила кода

- Проверка входных данных — zod-схема в `packages/shared`; та же схема в форме интерфейса. Ошибки сервера —
  `{ message, fields: { поле: текст } }` на русском, форма показывает их у полей.
- Новые права — только через `AccessService`; данные чужого направления не отдавать.
- Схема БД меняется **только новой миграцией**. Существующие миграции (в том числе `init`) не править.
  SQL удобно получить так: `npx prisma migrate diff --from-schema-datasource prisma/schema.prisma --to-schema-datamodel prisma/schema.prisma --script`,
  затем сохранить в `prisma/migrations/<дата>_<имя>/migration.sql` и проверить, что для существующих строк миграция пройдёт.
- После записи данных — `kpi.invalidate(directionId)`; у вкладок интерфейса — `invalidateQueries(['dir', code])`
  (и `['me', 'tasks']`, если влияет на «Мои задачи»).
- Графики и цвета: цвета только из CSS-переменных `theme.css` (`--status-good/warning/critical/none`, `--series-1..3`,
  `--seq-*`), отдельные для тёмной темы; состояние — всегда иконка + подпись, не только цвет; одна ось на график.
- Тяжёлые библиотеки (ECharts, OpenLayers) — только через динамический `import()`.
- Слои Mantine: карточка объекта (Drawer) — 200, карточка замечания — 300, окна поверх них — 400,
  выпадающие списки в таких окнах — `comboboxProps={{ zIndex: 1000 }}`.
- Телефон: ширина 375 px без горизонтальной прокрутки; таблицы — в `Table.ScrollContainer`; длинные переключатели сокращать.
- Стиль — как в окружающем коде: одинарные кавычки, длинные строки, комментарии по делу на русском.
  В проекте нет конфига Prettier: форматировать только с `--single-quote --print-width 160 --trailing-comma all`.

## Проверка перед сдачей

1. Типы сервера и интерфейса, `vitest`, сборка интерфейса.
2. Сквозная проверка API: небольшой node-скрипт против запущенного API под демо-учётками (права, ошибки, 409).
   Вход ограничен 10 попытками в минуту — в скриптах повторять вход после паузы при 429.
3. Браузер: нужные роли, светлая и тёмная тема, ширина 375 px. В свёрнутом окне Claude браузер не рисует кадры
   (OpenLayers, скриншоты) — проверять текстом страницы или попросить развернуть окно.
4. Документация в `docs/` и справка `apps/web/src/pages/HelpPage.tsx`, если поменялось поведение для пользователей.

## Подводные камни Windows

- Путь к проекту может содержать кириллицу — команды писать с полными путями в кавычках.
- `localhost` в Windows сначала идёт в IPv6, а API слушает IPv4: в проверках и прокси — `127.0.0.1`.
- `scripts/local.ps1` должен оставаться UTF-8 **с BOM** и CRLF (PowerShell 5.1), `local.cmd` — ASCII + CRLF.
  Это закреплено в `.gitattributes`; правки — обычным редактированием, не `node -e` с `$'` или обратными кавычками в строке.
- `deploy/*.sh` — LF и исполняемые; на сервере вызывать как `bash deploy/…`.
- `gh` может быть не установлен — тогда PR через сайт GitHub.
