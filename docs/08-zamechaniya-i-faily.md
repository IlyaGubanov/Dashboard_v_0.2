# 08. Замечания и файлы (этап 9а)

## Замечания

Замечание — недостаток на объекте, который нужно устранить в срок. У каждого есть номер в направлении (№ 37),
объект, при необходимости позиция, текст, категория, важность (низкая / средняя / высокая / критическая), срок и исполнитель.

### Жизненный цикл

```
Открыто ──► В работе ──► Устранено, на проверке ──► Принято
   │            │               │
   │            │               └──► Открыто (вернуть на доработку — с комментарием)
   └────────────┴───────────────────► Снято (выставлено ошибочно — с комментарием)
Принято / Снято ──► Открыто (открыть снова — с комментарием)
```

| Кто | Что может |
|---|---|
| Выставить замечание | куратор, администратор, руководство; ответственные за ввод — по своим объектам |
| Исполнитель — ответственный за ввод по объекту или назначенный исполнитель | взять в работу, отметить «устранено» (с комментарием и фото), комментировать |
| Проверяющий — куратор, администратор, автор замечания | принять, вернуть на доработку, снять, открыть снова; править текст, срок, важность, исполнителя, пока замечание не закрыто |

Замечания не удаляются: ошибочное снимается с комментарием. Каждый шаг — запись в ленте замечания и в журнале направления.
Если двое одновременно меняют одно замечание, второй получит сообщение «Замечание уже изменили» и обновлённую карточку.

**Просрочено** — срок прошёл, а замечание открыто или в работе. Замечание «на проверке» просроченным не считается:
исполнитель свою часть сделал.

### Где видно

- Вкладка **Замечания** направления: сводка (требуют устранения, просрочено, ждут проверки, закрыто за 30 дней — по щелчку
  фильтр), отбор по объекту, важности, категории, «мои», «просроченные», поиск; сначала просроченные, затем по важности.
  Число активных — на ярлыке вкладки, красным, если есть просроченные.
- **Карточка объекта**: вкладка «Замечания», строка «Замечаний не закрыто» в шапке.
- **Реестр объектов**: колонка «Замечаний открыто» (и в выгрузке CSV).
- **Сводка руководства**: показатели «Замечаний не закрыто» и «Замечаний просрочено» в конструкторе направлений
  (для МКД и Сетей «Просрочено замечаний» включён по умолчанию).

Показатели считаются на дату среза: для последней отчётной точки — на текущий момент, для прошлых — на конец дня плана.

## Файлы и фото

- К **объекту** (вкладка «Файлы и фото» в карточке): акты, схемы, фотофиксация. Добавляют те, кто вносит данные по объекту.
- К **шагу замечания** («устранено» — с фото результата). Фото прикладываются при действии; автор может дослать их в течение суток.

Кнопка «Сделать фото» на телефоне сразу открывает камеру. Фото больше 1,5 МБ уменьшаются в браузере до 2000 px
по большей стороне — 10-мегабайтный снимок уходит на сервер как 1–1,5 МБ.

| Ограничение | Значение |
|---|---|
| Размер файла | до 25 МБ |
| Типы | jpg, png, webp, gif, heic, pdf, doc(x), xls(x), ppt(x), txt, csv, zip, rar, 7z, dwg |
| Проверка | расширение из списка и начало файла должно ему соответствовать (страница или программа под видом картинки не примется) |
| Просмотр | только вошедшим участникам направления; картинки и PDF открываются в браузере, остальное скачивается |
| Удаление | «убрать» = архив: файл скрыт, но хранится; убрать может добавивший или куратор |

Файлы лежат в томе Docker `files_data` (`/data/files`), имена на диске случайные. **Резервная копия** — вместе с базой,
команды в [03-razvertyvanie.md](03-razvertyvanie.md).

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET / POST | `/api/directions/:code/remarks` | список (со справочниками для формы) / новое замечание |
| GET / PATCH | `/api/directions/:code/remarks/:id` | карточка с лентой и доступными действиями / правка (с `version`) |
| POST | `/api/directions/:code/remarks/:id/actions` | `{ action, text, fromStatus }` → `{ eventId }` |
| GET | `/api/attachments?entity=site\|remark_event&entityId=` | файлы и право добавлять |
| POST | `/api/attachments?entity=&entityId=&name=` | загрузка: тело — файл, `application/octet-stream` |
| GET | `/api/attachments/:id/file` | файл |
| POST | `/api/attachments/:id/archive` | убрать в архив |

## База данных

Миграция `20261030000000_remarks`: у `remark` — направление, номер (уникален в направлении), категория, версия;
новая таблица `remark_event` (лента); у `attachment` — признак архива.

Демо-данные: по 36 замечаний в МКД и Сетях в разных статусах (`is_example`). Добавить их в уже загруженную базу —
`npm run db:demo -- --remarks` (только в направления, где замечаний ещё нет).

## Проверено

- 38 сквозных проверок API: права (чужой объект, исполнитель не может принять, посторонний не комментирует), полный цикл
  с возвратом на доработку, 409 при устаревшем статусе и версии, загрузка фото, подделка под jpg, .exe, .html, файл 26 МБ,
  доступ к файлу без входа, архив файла, журнал, 10 одновременных замечаний — номера без повторов.
- Модульные тесты подсчёта открытых и просроченных на дату среза.
- В браузере: вкладка, карточка поверх карточки объекта, «устранено» с фото, правка, уменьшение фото 11,6 → 1,4 МБ,
  телефон 375 px без горизонтальной прокрутки.

## Панорамы 360°

Панорама — материал существующего вложения объекта (`materialType=PANORAMA360`), не новый раздел хранения.
Обычные вложения имеют `FILE` по умолчанию. Новая миграция добавляет тип, дату съёмки и описание без изменения старых строк.
В загрузку передаются `materialType`, `capturedOn` (ГГГГ-ММ-ДД) и необязательное `description` в параметрах запроса.
Панорамы допускаются только у объекта, независимо от отчётных периодов. Сохраняются автор и время загрузки.

Поддерживаются статичные сферические JPEG/PNG/WebP 2:1, ширина 1024–16384 px, до 64 млн пикселей.
Действующий предел 25 МБ не повышен. Проверяются сигнатура и полное декодирование, анимация (в том числе APNG)
отклоняется. Оригинал не меняется. Sharp (Apache-2.0) создаёт WebP: превью до 1200 px и просмотр до 4096 px.
Производные находятся рядом с исходником в существующем закрытом хранилище и входят в его резервную копию.
При архивировании скрываются все варианты; при ошибке загрузки временные производные удаляются.

`GET /api/attachments/:id/file?variant=preview|viewer` выдаёт производную с той же серверной проверкой доступа.
Без variant возвращается оригинал; `download=1` задаёт скачивание. Все варианты используют private cache и ETag
с обязательной проверкой авторизации при повторном запросе. Публичных файловых каталогов не добавлено.

В карточке «Файлы и фото» история отсортирована по дате съёмки, затем времени загрузки и ID. Несколько снимков
на одну дату разрешены. Pannellum (MIT, notice в `/licenses/pannellum.txt`) лениво загружается при открытии;
поддерживает вращение, касание, масштаб и полный экран. Загрузка изображения отменяется при закрытии/смене снимка.
Оригинал доступен по существующему праву чтения вложения; для карты он не загружается.

Единая карта получает ID/дату/количество панорам пакетно вместе с объектами. Последний снимок выбирается
по дате съёмки, затем времени загрузки и ID. Только при показе подсказки загружается статичное превью;
полный просмотрщик на карте не создаётся. Загрузка/архивирование обновляет запрос карты. На устройствах без hover
маркер открывает компактную информацию с кнопкой полной карточки; выбор совпадающих маркеров сохраняется.

Веб-клиент настраивает Zod в режиме `jitless` до создания схем: действующая CSP запрещает даже пробу `new Function`.
Правила валидации сохраняются; `unsafe-eval` не добавляется. Собранный клиент проверен локально с CSP из Caddy.
