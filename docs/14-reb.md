# РЭБ

Ремонтно-эксплуатационная база открывается в самостоятельном разделе `/reb`.
Производственные направления используются только как места распределения техники.
Ссылка `/d/reb` перенаправляет в новый раздел с сохранением фильтров и открытой записи.
Основной API — `/api/fleet`; прежний `/api/directions/reb/fleet` оставлен совместимым.

## Работа с данными

Обзор показывает единый реестр техники, использование, распределение, ДТП, расходы и потребности.
Неиспользуемая техника — представление того же реестра; история простоев меняет состояние только в своём периоде.
Распределение использует общие направления, объекты и сотрудников. Детализация доступна по направлениям, объектам и видам техники.
Штрафы, платные дороги и топливо открываются отдельными представлениями раздела «Расходы».
Топливо ведётся помесячно по виду и категории. В обзоре показан последний месяц выбранного периода;
график строится только при наличии нескольких реальных месячных точек. Среднедневные значения не вычисляются автоматически.
Участие в ДТП не устанавливает вину или долг. Подтверждённая ответственность вводится отдельно куратором с доступом к финансам и документом основания.
Изменения записываются в общий аудит. Сохранение проверяет версию, пересечения назначений и фактическое обеспечение заявок.

## Сверка техники

Данные о технике на объекте вносятся с двух сторон:

- **ответственный за объект** — при вводе за отчётную точку: общее число техники и, по желанию, разбивка по видам. Сумма по видам заменяет общее число;
- **РЭБ** — вкладка «Распределение техники»: конкретная машина назначается на объект на период.

Разделы сравниваются автоматически на дату среза направления. Состояния объекта: «Совпадает», «Разное количество», «Разные виды»
(итог равен, а виды различаются), «Только ответственный», «Только РЭБ». Если ответственный указал только общее число, сравнивается только итог.
Названия видов сравниваются без учёта регистра и «ё»; общий список видов — `MACHINERY_KINDS` в `packages/shared/src/machinery.ts`.
Вид машины в реестре вводится текстом: название вне списка будет показано как расхождение по видам.

Где смотреть: РЭБ → «Сверка техники» (все доступные направления) и плитка «Техники» на вкладке «Обзор» направления.
Для каждого объекта видно, кто и когда внёс данные с каждой стороны, сравнение по видам и список машин РЭБ.
Сверка показывает расхождения, но не меняет данные: исправляет та сторона, чьи данные неверны. Правка ответственного попадает в журнал объекта.

Показатели сводки считаются по данным ответственного, как и раньше; данные РЭБ на них не влияют.

Демо-парк: 250 единиц, из них 76 — малая механизация (`prisma/demo/fleet.ts`). Загрузить заново только его: `npx tsx prisma/demo/import.ts --fleet`
(техника, внесённая вручную, остаётся). На части объектов данные расходятся намеренно.

## Доступ

Глобальные роли, ограничения разделов и возможностей продолжают действовать.
Администратор управляет РЭБ; руководство имеет просмотр. Роль сотрудника назначается в общей карточке пользователя,
вкладка ролей, блок «РЭБ». Куратор управляет данными; редактор вводит в своей области; наблюдатель просматривает.
Ограничения финансов, персонала и журнала проверяются сервером, включая карточки, вложения, историю и поиск.
Редактор с ограничением по объектам может менять только связанные записи по доступным для ввода объектам.
В сверке сотрудник направления без роли в РЭБ видит итоги по видам на объектах своего направления, чтобы исправить расхождение, но не видит конкретные машины.
Скрытый раздел РЭБ закрывает сверку полностью, а скрытый раздел сотрудников — имена тех, кто внёс данные.

## Совместимость схемы

Миграция `20261031180000_reb_standalone_registry` создаёт `fleet_registry` и `fleet_member`,
копирует прежний идентификатор РЭБ, readonly и роли, затем переводит корневые внешние ключи таблиц РЭБ на новый реестр.
Физическое имя `directionId` сохранено для совместимости; это идентификатор реестра РЭБ, а не производственного направления.
Связи `targetDirectionId` и `siteId` остаются производственными. Прежняя строка направления сохраняется для исторических ссылок,
но исключается из меню, конструктора и производственной сводки. Новая установка не создаёт направление РЭБ.
Записи, идентификаторы, файлы, аудит и технические метаданные прежнего импорта не удаляются.
Формы импорта, исторических справок, расхождений первоисточников и конструктор справочников в пользовательском интерфейсе отсутствуют.

Миграцию следует проверять на копии целевой БД до планового развёртывания. Production не изменяется автоматически этим PR.
