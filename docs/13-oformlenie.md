# Оформление приложения

Администратор настраивает внешний вид без программиста в двух местах:

- меню «Администрирование» → **«Оформление»** (`/admin/appearance`) — общий вид для всех направлений;
- **«Конструктор направлений»** → направление → **«Плитки обзора»** — набор плиток на вкладке «Обзор» этого направления.

## «Оформление»: что можно менять

| Настройка | Где видно | Исходное значение |
|---|---|---|
| Название и подпись | шапка, страница входа, заголовок вкладки браузера | «МосводостокСтройТрест», «Информационно-аналитическая система» |
| Шрифт | весь текст; если шрифта нет на компьютере — Segoe UI или Arial | Montserrat |
| Размер текста, 12–18 px | обычный текст; подписи, таблицы и заголовки — пропорционально | 14 px |
| Размер текста в направлениях, 12–24 px | все вкладки направления, карточки объектов и замечаний, окна ввода, плитки, крупные числа, подписи графиков — во всех направлениях, в том числе новых. Меню, шапка и сводка — по общему размеру | 16 px |
| Скругление углов, 0–16 px | карточки, кнопки, поля, вкладки, меню, плитки | 4 px |
| Плитки показателей: вид | полоса слева / рамка / заливка | полоса слева |
| Плитки: размер числа и подписи | 14–36 px и 10–16 px | 16 и 12 px |
| Плитки: сколько в ряду | 2–6 на широком экране; на телефоне всегда по две | 4 |
| Меню направлений: подпись под названием | число объектов («4 школ») / полное название / без подписи | число объектов |
| Меню направлений: размер подписи | 10–14 px | 11 px |
| 20 цветов — отдельно для светлой и тёмной тем | основной цвет, фон, карточки, текст, линии, подпись в меню, состояния, серии графиков, полоса «факт / план», фон и полоса плиток | цвета брендбука (`docs/ui-refresh`) |

Логотип не настраивается: это файл `apps/web/public/brand/logo.svg`.
Слово после числа в меню («школ», «адресов») — в конструкторе: «Основное» → «Как называть объекты».

## «Плитки обзора» в конструкторе направления

Список всех плиток вкладки «Обзор»: стандартные (объекты, отстают, критично, выполнено, люди, техника, деньги) и
«Показатели сводки» этого направления. Для каждой плитки:

- галочка — показывать или скрыть;
- стрелки — порядок;
- «Своя подпись» — пусто, значит стандартная;
- «Цвет» — как у всех, смысловой («как „критично“», «как „отставание“», основной, серия графика) или свой код.
  Смысловые цвета берутся из «Оформления» и сами меняются в тёмной теме; свой код одинаков в обеих темах.

Некоторые плитки появляются только при данных: «отстают» и «критично» — при графике, люди, техника и деньги — если их вносят.
Плитки, которых ещё нет в настройке (например, новый показатель сводки), показываются в конце.

## Как это работает

- Пока администратор правит «Оформление», изменения видны **только у него**, но сразу во всём приложении: можно открыть
  сводку или направление, посмотреть и вернуться — черновик не пропадёт до перезагрузки страницы. Вверху других страниц
  в это время полоса «Оформление не сохранено» с кнопками «Вернуться к настройке» и «Отменить изменения».
- «Сохранить для всех» — оформление действует для всех пользователей, в том числе на странице входа. Запись — в журнал.
  «Плитки обзора» действуют сразу после «Сохранить плитки».
- Справа — образец элементов и проверка контраста: если текст или значок плохо читается на своём фоне (контраст ниже 4,5 для
  текста и 3 для значков и графиков), появится предупреждение с указанием, что именно поправить.
- «Вернуть исходное оформление» подставляет значения брендбука; для всех — после сохранения.

## Для разработчика

| Что | Где |
|---|---|
| Схема, список цветов, подписи, исходные значения | `packages/shared/src/appearance.ts` (`appearanceSchema`, `DEFAULT_APPEARANCE`) |
| Хранение оформления | `app_setting`, ключ `ui.appearance`; новой миграции не нужно |
| API оформления | `GET /api/appearance` — без входа; `PUT /api/admin/appearance` — администратор (`apps/api/src/appearance/`) |
| Применение | `apps/web/src/ui/appearance.tsx`: тема Mantine (`theme.ts → buildTheme`) и CSS-переменные поверх `theme.css`; там же черновик |
| Страница | `apps/web/src/pages/admin/AppearancePage.tsx` |
| Плитки обзора: схема | `packages/shared/src/admin.ts` (`OVERVIEW_TILES`, `TILE_COLOR_TOKENS`, `overviewTilesSchema`) |
| Плитки обзора: хранение и API | `direction.settings.overviewTiles`; `PUT /api/admin/directions/:code/tiles`; приходят в `GET /api/directions` (`overviewTiles`) |
| Плитки обзора: показ | `apps/web/src/ui/overviewTiles.ts` (`arrangeTiles`), `ui/Metric.tsx`, `pages/direction/OverviewTab.tsx` |

Размер текста в направлениях: страница направления (`DirectionPage`) и её окна (`Drawer`/`Modal` в `pages/direction/`)
помечены классом `direction-page`; внутри него `ui/appearance.tsx` переопределяет `--mantine-font-size-*` и
`--mantine-h*-font-size` и задаёт множитель `--text-scale` (размер / 14). Жёстко заданные размеры на этих страницах
писать как `calc(32px * var(--text-scale, 1))`; новое окно направления — с `className="direction-page"`.

Показатели сводки в плитках — ключи `kpi:0…kpi:5` по месту в «Показателях сводки» (`KpiTile.slot`). Если показатели
переставить, свой цвет и подпись останутся за местом, а не за показателем — проверьте «Плитки обзора» после перестановки.

Значения по умолчанию в `theme.css` и `DEFAULT_APPEARANCE` должны совпадать. Новый цвет: ключ в `APPEARANCE_COLORS`, подпись
в `APPEARANCE_COLOR_INFO`, значения в `DEFAULT_APPEARANCE`, CSS-переменная в `CSS_VARS` (`ui/appearance.tsx`) и в `theme.css`.
Сохранённые раньше настройки без нового поля берут его из исходных (`mergeAppearance`).
Браузер запоминает последнее оформление (`localStorage`, `mvs.appearance`), чтобы при открытии не мелькали исходные цвета.
MySQL хранит JSON с ключами в своём порядке — сравнивать настройки по значениям, а не строкой.
