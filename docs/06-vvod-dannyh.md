# Ввод данных (этап 7а)

Код: API — [apps/api/src/entry](../apps/api/src/entry), экраны — [EntryTab](../apps/web/src/pages/direction/EntryTab.tsx),
[JournalTab](../apps/web/src/pages/direction/JournalTab.tsx). Вкладка «Ввод данных» видна тем, кому разрешено вносить данные.

## Как работает неделя

1. **Куратор открывает неделю** («Открыть новую неделю»; любая дата приводится к понедельнику). Значения сразу видны
   перенесёнными с прошлой недели — с пометкой «значение с 26.10.2026».
2. **Ответственные вносят факт** по своим объектам: статус, готовность или объём, КС-2, оплачено, примечание;
   по объекту — людей и технику (там, где они ведутся). Изменённые поля подсвечиваются, сохраняются одной кнопкой.
   Если по объекту ничего не изменилось — «Без изменений — подтвердить значения»: объект отмечается как внесённый.
3. **Контроль заполнения**: «Внесено в эту точку: N из M ваших объектов», фильтр «Только не внесённые»,
   на вкладке «Ответственные» — кто внёс, кто нет.
4. **Куратор проверяет и закрывает неделю** («Проверено, закрыть неделю», комментарий попадает в журнал).
   В сводке исчезает отметка «не проверено».
5. При необходимости куратор **возвращает неделю в работу**; администратор может **заблокировать** окончательно сданную.

## Права

| | Открыта | Закрыта куратором | Заблокирована |
|---|---|---|---|
| Ответственный за ввод | свои объекты (всё направление / лоты / назначенные) | — | — |
| Куратор | все объекты | все объекты | — |
| Администратор | все | все | все |
| Открыть новую / закрыть / вернуть | куратор, администратор | | только администратор |

## Отчётные программы Благоустройства

Ручной ввод доступен после снятия настройки «Только просмотр» и только сотрудникам с действующими правами ввода.
Выберите программу отчёта (из настроек направления и существующих периодов), затем отчётную точку.
Куратор или администратор может открыть новый отчёт выбранной программы. Закрытые и заблокированные отчёты
не становятся редактируемыми автоматически: сначала требуется явно вернуть конкретный отчёт в работу.
Для REPORT это правило действует и для администратора; недельный порядок прав из таблицы выше сохраняется.

Вводятся фактические объёмы поддерживаемых позиций, люди, техника, отчётный статус и число замечаний по отчёту.
Значения переносятся в пределах своей программы. Исходные атрибуты импортированных объёмов сохраняются.
При сохранении объекта в новом REPORT подтверждаются также показанные перенесённые значения его позиций.
Другие объекты автоматически не подтверждаются: новый отчёт заполняется по мере ввода, как самостоятельный срез.
Изменения источника и значений записываются в журнал. Seed сохраняет существующие настройки направления;
защита повторного импорта учитывает также вручную заполненную сводку источника.

«Сводные данные источника» — отдельное сохранение куратором/администратором с проверкой версии. Укажите область
(организация/город), организацию, источник и страницу. Можно внести площадь, количество объектов по этапам,
ресурсы, объёмы, электрику/АСУДД/ООТ и количества нарушений по группам/типам ЦККБ. Неизвестное оставляйте пустым.
Эти значения не прибавляются к KPI объектов и не создают карточки нарушений. При конфликте чужой версии
черновик остаётся в форме; отмена правок загружает актуальную сводку.

В обзоре «Выполнено по объёмам» использует существующий критерий выполнения позиций,
а «Завершено по отчётному статусу» — настроенные отчётные статусы завершения. Дата, знаменатель и методика
показаны отдельно. Нажатие открывает список объектов, включая две выборки расхождений между методиками.
Число замечаний по отчёту доступно с объектом, программой, датой и источником; оно не суммируется с реестром замечаний.

## Защита данных

- **Одновременная правка.** У каждой записи есть версия. Если запись изменили, пока пользователь вносил свою правку,
  сохранение отклоняется целиком (ничего не записывается) с перечнем конфликтующих позиций; несохранённые правки остаются в форме.
- **Проверка значений** на сервере и в форме одной и той же схемой: готовность 0–100 %, объёмы и деньги не отрицательные, статус из справочника.
- **Права проверяются на сервере** для каждого объекта: подменить запрос в браузере не поможет.
- **Пересчёт сводки** — сразу после сохранения.
- **Внесённые вручную данные** снимают пометку «демо». Перезагрузка демо-данных (`db:demo --force` / `--clear`)
  пропускает направление, если в нём есть ручной ввод; удалить его можно только флагом `--delete-manual-data`.

## Журнал изменений

Вкладка «Журнал»: когда, кто, объект, позиция и неделя, что было → что стало (статусы — названиями),
открытие и закрытие недель с комментариями, загрузки данных. Фильтр по датам, постранично.

## API

| Запрос | Что делает |
|---|---|
| `GET /api/directions/:code/entry/:periodId` | лист ввода: действующие значения, права, какие поля показывать |
| `PUT /api/directions/:code/entry/:periodId` | сохранить `{ items: [...], reports: [...] }` (все или ничего; 409 при конфликте версий) |
| `POST /api/directions/:code/periods` | открыть точку `{ date }` |
| `POST /api/directions/:code/periods/:id/status` | `{ status: OPEN \| CLOSED \| LOCKED, comment }` |
| `GET /api/directions/:code/audit?from&to&skip&take` | журнал |

Миграция БД: [20261029000000_entry](../apps/api/prisma/migrations/20261029000000_entry/migration.sql) — версия и автор правки у показателей объекта.

## Проверено (25 сценариев на демо-данных)

Ответственная вносит только по своим 22 адресам из 42; чужой адрес — отказ; 150 % — отказ; закрытая неделя — отказ
с понятной причиной; одновременная правка — 409; куратор закрывает и возвращает неделю, не может заблокировать;
новая неделя приводится к понедельнику, значения переносятся; «без изменений» отмечает объект; контроль заполнения
видит, кто внёс; журнал хранит «было → стало»; сводка пересчитывается сразу; ручной ввод в Благоустройстве запрещён.

# Управление направлением и надстройки (этап 7б)

Код: API — [apps/api/src/manage](../apps/api/src/manage), экраны — [ManageTab](../apps/web/src/pages/direction/ManageTab.tsx),
[SiteEditor](../apps/web/src/pages/direction/SiteEditor.tsx), [TrackerEditor](../apps/web/src/pages/direction/TrackerEditor.tsx).

## Вкладка «Управление» (куратор и администратор)

| Раздел | Что можно |
|---|---|
| **Объекты** | создать объект; изменить паспорт (название, раздел, адрес, округ, сроки, подрядчик, проектировщик, лимит, координаты, примечание) и **доп. поля направления** (у Школ — тип здания, площадь, пищеблок…); отправить в архив и вернуть |
| ↳ Позиции работ | добавить, изменить (вид работ, своё название, объём, стоимость, сроки, ответственный, исполнитель); убрать: позиция с внесённым фактом уходит в архив (история сохраняется), ошибочная без факта удаляется |
| ↳ Ответственные | куратор объекта, ответственный за ввод, ответственный подрядчика, прораб, ГИП — из списка пользователей |
| **Разделы** | добавить, переименовать, в архив |
| **Виды работ** | добавить, изменить (группа, единица, вес, типовые сроки), в архив |
| **Организации** | подрядчики, проектировщики, поставщики, экспертиза; ИНН проверяется |

Из карточки объекта кнопка «Изменить объект» сразу открывает редактор.

## Надстройки в карточке объекта

Закупки, индивидуальные испытания, МГЭ (Школы), документация (Сети): «Внести изменения» → поля по типу этапа
(проценты, да/нет, даты, статусы из списка, текст), изменённое подсвечивается, сохраняется только оно.
Вносить может каждый, у кого есть право вносить данные по этому объекту.

## Защита

- Права на сервере: структуру меняют только куратор направления и администратор; надстройки — по праву ввода на объект.
- Нельзя сослаться на раздел, вид работ или организацию другого направления.
- Доп. поля проверяются по их описанию (число, процент 0–100, дата, значение из списка, ссылка); неизвестное поле — ошибка.
- Одновременная правка объекта — по версии (409).
- Всё пишется в журнал; сводка пересчитывается сразу.

## API

`GET /api/directions/:code/manage` (справочники и список объектов), `GET|PATCH /manage/sites/:id`, `POST /manage/sites`,
`POST /manage/sites/:id/archive`, `PUT /manage/sites/:id/assignments`, `POST /manage/sites/:id/items`, `PATCH /manage/items/:id`,
`POST /manage/items/:id/archive`, `POST|PATCH /manage/sections`, `/manage/work-types`, `/manage/organizations`,
`PUT /manage/sites/:id/trackers/:tracker`.

## Проверено (29 сценариев)

Ответственная видит справочники, но не может ничего создать; куратор создаёт раздел, подрядчика (повтор и неверный ИНН —
отказ), объект (окончание раньше начала и неизвестное доп. поле — отказ), правит с версией (старая версия — 409),
добавляет позицию (вид работ чужого направления — отказ), назначает ответственных; новый объект сразу появляется
в листе ввода ответственной и в сводке; позиция с фактом — в архив, без факта — удаляется; объект в архиве пропадает
из сводки; надстройки: 150 % и статус не из списка — отказ, корректные значения видны на сводном экране; ответственная
другого направления не может вносить надстройки; журнал фиксирует все действия.
