# 11. Запуск на своём компьютере

Чтобы посмотреть приложение, показать его коллегам или попробовать ввод данных — без сервера и домена.
Два варианта:

| | А. Windows без Docker (проще) | Б. Docker Desktop |
|---|---|---|
| Что нужно | Node.js 22+, MySQL 8.0+ | Docker Desktop |
| Адрес | http://localhost:5173 | https://localhost (браузер предупредит о сертификате) |
| Похоже на сервер | нет: интерфейс в режиме разработки | да: те же контейнеры, что на сервере |

## А. Windows без Docker

### Что установить один раз

1. **Node.js 22 LTS** или новее — https://nodejs.org (установщик Windows, всё по умолчанию).
   Проверка в командной строке: `node -v` → `v22…` или выше.
2. **MySQL 8.0** или новее. Если MySQL уже стоит — подойдёт он. Если нет — MySQL Installer с https://dev.mysql.com/downloads/installer/
   (вариант «Server only», пароль root запомните).
3. **Код проекта**:
   - с git: `git clone https://github.com/IlyaGubanov/Dashboard_v_0.2.git`;
   - без git: на странице репозитория **Code → Download ZIP**, распаковать в любую папку.

### Пользователь MySQL

Проще всего указать `root`: скрипт сам создаст базу `mvs_local`. Если не хотите давать root — создайте отдельного
пользователя (MySQL Workbench или `mysql -u root -p`):

```sql
CREATE DATABASE mvs_local CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'mvs'@'localhost' IDENTIFIED BY 'придумайте-пароль';
GRANT ALL PRIVILEGES ON mvs_local.* TO 'mvs'@'localhost';
```

### Первая настройка (5–10 минут)

Откройте папку проекта в проводнике, в адресной строке наберите `cmd` и нажмите Enter — откроется командная строка в этой папке.

```bat
local.cmd setup
```

Скрипт спросит:

| Вопрос | Что ответить |
|---|---|
| Адрес сервера MySQL | Enter (`localhost`) |
| Порт | Enter (`3306`) |
| Пользователь | `root` или созданный выше `mvs` |
| Пароль | пароль этого пользователя (при вводе не отображается) |
| Имя базы | Enter (`mvs_local`) |
| Пароль администратора приложения | Enter (`Admin2026local`) или свой: от 10 символов, буквы и цифры |

Дальше всё сделается само:

- установит зависимости;
- создаст таблицы;
- загрузит демо-данные исходного дашборда (Школы, МКД, Сети, Благоустройство);
- заведёт демо-учётки по ролям;
- соберёт сервер.

Ответы сохраняются в файл `local.env` в папке проекта. В git он не попадает. Повторный `setup` больше ничего не спрашивает.

### Запуск

```bat
local.cmd start
```

Откроется отдельное окно с сервером (API) — не закрывайте его. В браузере откроется **http://localhost:5173**.
Остановить: в окне, где запускали, нажмите **Ctrl+C**. На вопрос «Завершить выполнение пакетного файла [Y(да)/N(нет)]?» ответьте `Y`.
Окно API закроется само; если осталось — закройте его.

### Учётные записи

| Логин | Пароль | Что увидите |
|---|---|---|
| `admin` | `Admin2026local` (или ваш из `setup`) | всё, плюс «Пользователи и роли» и «Конструктор направлений» |
| `rukovod` | `Rukovod2026demo` | руководство: сводка и просмотр, без ввода |
| `kurator` | `Kurator2026demo` | куратор МКД и Сетей: недели, «Управление», проверка замечаний |
| `vvod` | `Vvod2026demo` | ответственный за ввод МКД (лоты 1 и 2): лист ввода, «Мои задачи», замечания |

Смена пароля при входе для этих учёток отключена — это только для показа.
Скрипт демо-учёток откажется работать, если база не на этом компьютере, чтобы такие пароли не попали на сервер.

### Что посмотреть

- **Ввод данных**: МКД → вкладка «Ввод данных».
  - Неделя с 26.10 уже заполнена демо-данными.
  - Чтобы ввести с нуля, нажмите «Открыть новую неделю» (под `admin` или `kurator`): значения перенесутся с прошлой недели.
  - Под `vvod` видны только свои объекты.
  - Сузьте окно браузера — появится вид для телефона с кнопками +5 / +10 / 100%.
- **Мои задачи** — колокольчик вверху: под `vvod` и `kurator`.
- **Замечания** — вкладка направления: «Взять в работу», «Устранено» с фото, «Принять».
- **Прогноз** — вкладка «Объекты», колонка «Прогноз».
- **Справка** — внизу меню.

### Другие команды

| Команда | Что делает |
|---|---|
| `local.cmd demo` | вернуть демо-данные к исходному виду: всё, что внесли вручную, удалится (спросит подтверждение) |
| `local.cmd setup` | после обновления кода (`git pull` или новый ZIP): поставит зависимости, применит новые миграции, пересоберёт; данные сохранятся |

### Если что-то не так

| Сообщение | Что сделать |
|---|---|
| «не найден Node.js» / «нужен Node.js 22» | установить Node.js 22 LTS, открыть командную строку заново |
| «API не запустился» | посмотреть текст в окне API. Частые причины: не запущен MySQL (Службы Windows → MySQL80 → Запустить), неверный пароль в `local.env` (исправьте строку `DATABASE_URL` или удалите файл и выполните `setup` заново), занят порт 3000 (`netstat -ano \| findstr :3000`) |
| `Access denied for user` | у пользователя MySQL нет прав на базу — выполните команды из раздела «Пользователь MySQL» |
| Порт 5173 занят | vite сам выберет следующий (5174…) и напишет адрес в окне |
| Пароль MySQL со спецсимволами | работает: скрипт кодирует его в адресе базы |
| После обновления кода странности в браузере | Ctrl+F5 |

## Б. Docker Desktop

Те же контейнеры, что на сервере, но с самоподписанным сертификатом. Здесь Docker не было, поэтому этот вариант
не проверен запуском — первым шагом посмотрите `docker compose logs api caddy`.

1. Установить Docker Desktop (https://www.docker.com/products/docker-desktop/), запустить.
2. В папке проекта скопировать `.env.example` в `.env` и поменять:
   ```ini
   DOMAIN=localhost
   TLS_MODE=internal
   ADMIN_PASSWORD=Admin2026local
   DEMO_DATA=true
   ```
   Пароли `MYSQL_*` для своего компьютера можно оставить как есть.
3. Запуск (первый раз собирается 5–10 минут):
   ```bat
   docker compose up -d --build
   ```
4. Демо-учётки по ролям:
   ```bat
   docker compose exec -e DEMO_USERS=true api npx tsx prisma/demo/users.ts
   ```
   Не делайте этого на сервере с доступом из интернета: пароли демо-учёток известны.
5. Открыть **https://localhost**. Браузер предупредит о сертификате: «Дополнительно» → «Перейти на сайт».

Остановить: `docker compose down` (данные сохранятся). Удалить вместе с данными: `docker compose down -v`.

## Для разработчиков: режим с перезагрузкой при правках

```bat
set DATABASE_URL=mysql://root:пароль@127.0.0.1:3306/mvs_local
set COOKIE_SECURE=false
npm run dev:api
```

Во втором окне: `npm run dev:web`. Сервер и интерфейс перезапускаются при сохранении файлов.
