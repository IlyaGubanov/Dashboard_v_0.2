# Штатная численность

Раздел `/staffing` — самостоятельный кадровый реестр по подразделениям и категориям АУП / ВП / ОП. Численность не привязана к пользователям приложения и производственным показателям направлений.

## Анализ исходных данных

Источник: `Численность ТРЕСТА.xlsx`, лист `АНО МосводостокСтройТрест`, строки 6–46. В книге 109 листов: кадровые выгрузки, оперативные сводки, вакансии, приём/увольнение и другие отчёты. По согласованию в раздел переносится только выбранное штатное расписание: 41 подразделение, штат, фактическая численность, категории и функции. Персональные и медицинские сведения из других листов не импортируются.

Это не 41 подразделение, а 11 укрупнённых блоков сводки: ГУП МВС (СМУ+РСУ+ТЛС) — 508, РЭБ (без ТЛС) — 481, РСУ СР+УСР от Учредителя — 429, РСУ-1 — 524, РСУ-2 — 541, РСУ-3 — 1 358, РСУ-5 — 4, РСУ-6 — 260, АУП — 323, Управление гражданского строительства — 11, Управление обеспечения и эксплуатации производственной базы — 45; итого 4 484, как в строке 17. Штата по блокам в сводке нет (указано только «Утверждено 4 547 штатных единиц»), поэтому штат в этом срезе пустой, а не выдуманный; ФИО руководителя из названия блока не переносится. Суммы совпадают с контрольной строкой 47 исходного листа. Они не означают полноту заполнения: Excel SUM игнорирует пустые ячейки. Пустые значения и текст «нет» перенесены как отсутствие данных, числовые нули сохранены. Данные 2024 года по численности отсутствуют и не превращаются в искусственные нулевые срезы.

## Распределение по РСУ

На «Обзоре» — кольцевая диаграмма «Распределение по РСУ и подразделениям», как столбец «Процент от общей численности» в листе «СВОД по подразделениям». Рядом таблица: группа, численность, доля. Переключатель «Факт, чел. / Штат, ед.» меняет показатель, порядок и цвета групп остаются прежними (их задаёт факт). Доля считается от известной суммы; если у части подразделений нет данных, под диаграммой стоит пометка «△ Без данных». Нажатие на сектор или группу раскрывает её должности (см. ниже); кнопка «Подразделения группы» открывает вкладку «Подразделения» с фильтром (параметр адреса `group`, показатель диаграммы — `pie=planned`).

Группа задаётся в карточке подразделения полем «Группа на диаграмме» (до 120 символов, можно выбрать из уже встречающихся). Пустое поле — группа определяется по названию:

| Название подразделения содержит | Группа |
|---|---|
| «РСУ-N» | РСУ-N |
| «эксплуатационная база» | РЭБ (без ТЛС) |
| ровно «Строительно-монтажное управление», ровно «Ремонтно-строительное управление», «Транспортно-логистическая служба» | ГУП МВС (СМУ+РСУ+ТЛС) |
| «от Учредителя» | РСУ СР+УСР от Учредителя |
| «Управление гражданского строительства», «Управление обеспечения и эксплуатации производственной базы» | одноимённая группа |
| остальное | АУП |

На 01.07.2026 по этим правилам: РСУ-3 — 1 488, РСУ-1 — 684, РЭБ — 614, РСУ-2 — 564, ГУП МВС — 455, АУП — 321, РСУ-6 — 295, УОЭПБ — 44, УГС — 39, РСУ СР+УСР — 35 (итого известный факт 4 539). Цвета — разноцветная палитра `--cat-1…10` из `theme.css` (отдельные тона для светлой и тёмной темы) по убыванию факта, соседние группы всегда разного тона; группа «АУП» (и группы после десятой) — нейтральный `--status-none`; группы различаются подписями в таблице, а не только цветом. Поле хранится внутри среза (JSON), миграция БД не нужна; в выгрузке CSV добавлена колонка «Группа».

## Оформление обзора

В заголовке — дата данных среза крупным шрифтом и рядом текущая дата (по Москве). Четыре карточки показателей окрашены разными цветами палитры `--cat-*` (полоса слева, светлый фон, значок); числа — обычным цветом текста, чтобы читались в обеих темах. График «Численность по срезам»: штат — оранжевый, факт — тёмно-синий. Блок «Структура по категориям» убран.

Диаграмма распределения на широком экране (от 992 px) — полукольцо, повёрнутое к таблице: секторы идут сверху вниз в том же порядке, что и строки, и каждая соединена со своей строкой линией того же цвета, поэтому линии не пересекаются. На телефоне и узком окне — полное кольцо над таблицей, без линий. Текст таблицы групп — 15 px.

## Должности по группам

Нажатие на группу (строку или сектор) раскрывает её прямо в таблице: план, факт и потребность по группе, приём/увольнение за последние 4 недели внесённых данных и список должностей «План / Факт / Потребность» (первые 12, кнопка «Показать все»). Потребность = max(план − факт, 0); должности с потребностью — сверху, со значком △. Сектор раскрытой группы выдвигается, её линия выделяется, остальные приглушаются. Кнопка «Подразделения группы» открывает вкладку «Подразделения» с фильтром.

Должности хранятся внутри среза (поле `positions`). В срезе 26.10.2026 — 279 должностей:

- факт — лист «По должностям 26.10.2026»: строки разных разрядов одной должности сложены («Маляр строительный 5 разряд» → «Маляр строительный»), сумма по каждой группе совпадает с итогом группы (4 484 всего);
- план = факт + вакансии из листа «вакансии» (выбрано заказчиком до получения отдельной таблицы плана). Строки «Участок…», «Отдел…», «Группа…», «Гараж» — промежуточные итоги и не считаются. Вакансии ТЛС из блока РЭБ отнесены к ГУП МВС (СМУ+РСУ+ТЛС), как в сводке. Вакансии без пары в фактическом списке добавлены должностью с фактом 0 (например, РСУ-1 «Газосварщик» — план 5, факт 0);
- вакансии есть по РСУ-1 (88), РСУ-2 (149,5), РСУ-3 (82,5), РЭБ (49), УСР (21), ГУП МВС / ТЛС (10). У РСУ-5, РСУ-6, АУП, УГС и УОЭПБ вакансий по должностям в источнике нет — план у них пустой, показывается только факт.

Расхождения в самом листе «вакансии», которые стоит проверить: РСУ-3 — итог блока 95,5, а сумма участков 82,5; РЭБ — итог 64, сумма должностей 59; РСУ-5 — итог 18 без разбивки по должностям. Дата листа вакансий в файле не указана. Когда придёт отдельная таблица плана по должностям, план заменяется ею.

## Приём и увольнение

Вкладка «Приём и увольнение»: переключатель «Дни / Недели / Месяцы» (неделя — с понедельника), фильтр по группе, период «С / По» (по умолчанию — последние 8 недель, но не раньше первого внесённого дня). Карточки «Принято», «Уволено», «Сальдо» и число дней с данными; график — столбик вверх «принято», вниз «уволено», линия — сальдо; таблица по группам за период (нажатие на группу показывает на графике только её).

Данные хранятся по дням (таблица `staffing_movement_day`): один день — строки «группа / принято / уволено» и примечание. Ответственный за кадровые данные нажимает «Внести за день» (по умолчанию — вчера, как «до 09.00 за предыдущий день» в Excel); если день уже внесён, форма открывает его для правки. Пустое поле сохраняется как 0. Правка проверяет версию: устаревшая — HTTP 409, повторное создание того же дня — 409. Каждое сохранение пишется в журнал. Руководство видит вкладку без кнопки ввода.

Начальные данные — лист «Приемыувольнения»: 43 дня с 14.09 по 26.10.2026, 11 групп; принято 685, уволено 534. По каждой группе сверено: численность на 14.09 + принято − уволено = численность на 26.10 (например, ГУП МВС: 517 + 2 − 11 = 508). Переводы между управлениями в источнике учтены как приём и увольнение (18.09 — 224 человека из РСУ-3 в УСР), это видно пиком недели 14–20.09. Комментарии листа (в них есть ФИО) не переносятся.

## Как вести раздел

1. В меню выберите «Штатная численность». «Обзор» показывает показатели всего среза, историю на фактические даты, распределение по РСУ с должностями и подразделения, требующие внимания.
2. Выберите срез и период сравнения. Пропущенные месяцы не интерполируются. Дата каждого нового среза выбирается вручную в пределах указанного месяца; один срез на месяц.
3. «Новый срез» создаёт пустой месяц или копирует подразделения, категории, функции и штат выбранного среза. Факт и примечания строк в копии пустые: их нужно заполнить заново. Старый срез сохраняется.
4. Во вкладке «Подразделения» доступны поиск, категория, состояние, сортировка, карточка строки, добавление и редактирование. Верхняя сводка относится ко всему срезу, нижние итоги — к найденным строкам. Пустое поле означает отсутствие данных, 0 — подтверждённое нулевое значение. Штат может быть дробным, факт — целое число людей.
5. Отметьте строки для массового архивирования или восстановления. Архив строк доступен в фильтре состояния; архив срезов — переключателем над показателями. Исторические срезы не изменяются при переименовании или архивировании строки в другом месяце.
6. «ФОТ по годам» хранит отдельные годовые наборы: можно добавить год, указать фактический период/основание, редактировать названия, категории и суммы, добавлять или убирать строки. Пустые суммы отличаются от нулевых. Удаление строки в форме сохраняется только после «Сохранить ФОТ», прежнее значение остаётся в журнале БД.
7. Выгрузка — CSV в кодировке UTF-8 с BOM для Excel. Выгружается найденный набор, включая примечания и функции; потенциальные Excel-формулы экранируются. В меню также доступна печать текущего представления.

## Расчёты

- Штат и факт: суммы известных значений с видимым числом заполненных подразделений.
- Дефицит: сумма `max(штат − факт, 0)` только по заполненным парам.
- Превышение: сумма `max(факт − штат, 0)` по тем же парам. Не уменьшает дефицит в других подразделениях.
- Укомплектованность: `сумма факта / сумма штата` по заполненным парам; при нулевом знаменателе — «—». Может превышать 100%.
- Изменение: разница факта у одной записи подразделения между выбранными срезами. Если хотя бы одно значение отсутствует или подразделение не найдено, показывается «—». Сравнение с тем же срезом исключено.

## Доступ и сохранение

Администратор редактирует весь раздел. Руководство просматривает данные. Администратор или куратор активного направления назначает кадровых ответственных через меню «Ответственные за данные». Куратор получает просмотр и возможность назначения; редактирование численности получает после назначения ответственным. Назначенные сотрудники редактируют все кадровые срезы и ФОТ. Конкретные сотрудники заранее не назначались.

Скрытие раздела в карточке пользователя запрещает доступ и на сервере. Запрет финансов исключает ФОТ из ответа API и запрещает его изменение. Запрет журнала и выгрузки отражается в доступных действиях. Переключатель «Финансы» скрывает финансовое представление для совещаний в рамках существующих правил приложения.

Каждое изменение пишется в `AuditLog` в одной транзакции с данными. Срез и годовой ФОТ имеют версию: устаревшая правка получает HTTP 409 и не перезаписывает чужие изменения. Форма сохраняет введённые значения при ошибке. Для повторной правки после конфликта закройте форму, обновите раздел, проверьте актуальные значения и внесите изменения заново.

Первичная загрузка через меню («Загрузить исходные данные») добавляет отсутствующие исходные периоды — 01.01.2025, 01.07.2025, 01.01.2026, 01.07.2026, 26.10.2026 — и годы ФОТ, сохраняя существующие записи, в том числе архивные. Это импорт согласованного исходного файла, не универсальный загрузчик произвольных Excel.

## Развёртывание и проверка

Новая миграция `20261031153000_staffing` добавляет таблицы `staffing_period`, `staffing_payroll`, `staffing_editor`. Старые таблицы не меняются. После получения изменений: `npm run db:generate`, `npm run db:migrate`, сборка приложения. На сервере используется обычный процесс обновления проекта с миграциями.

Миграция `20261031210000_staffing_movements` добавляет таблицу `staffing_movement_day` (приём и увольнение по дням). Должности хранятся в JSON среза, отдельной миграции не требуют. Загрузка «Загрузить исходные данные» добавляет отсутствующие дни приёма/увольнения и должности в срез 26.10.2026, если в нём их ещё нет; существующие данные не перезаписываются.

`scripts/extract-staffing-details.mjs <исходный.xlsx> apps/api/src/staffing/source.json` извлекает должности (факт + вакансии) и приём/увольнение по дням, сверяет суммы с итогами листов и печатает расхождения листа «вакансии».

`scripts/extract-staffing.py <исходный.xlsx> <source.json>` воспроизводит извлечение согласованных агрегатов, включая срез 26.10.2026 со сверкой суммы блоков с итогом сводки. Источник хранится в `apps/api/src/staffing/source.json`.

Проверки: тесты расчётов/валидации/доступа и интеграционные тесты на MySQL; `scripts/verify-staffing.cjs` проверяет HTTP API временными учётными записями, включая большой запрос и коды 400/403/409. Команда `node scripts/verify-staffing.cjs cleanup` удаляет временные учётки и тестовые срезы. Проверочный скрипт использует `DATABASE_URL` из окружения; предназначен для локальной тестовой базы.

Браузерная проверка: после `node scripts/verify-staffing.cjs` войдите во временную учётку `staffing-qa-admin` и выполните `playwright-cli -s=staffing run-code --filename=scripts/verify-staffing-browser.js`, затем `node scripts/verify-staffing.cjs cleanup`. Пароль тестовых учёток указан в проверочном скрипте; они создаются только на время проверки.

Проверено при реализации: 33 теста, типы всех пакетов, сборки сервера и интерфейса, HTTP API и браузерные сценарии. Просмотрены светлая и тёмная темы, ширины 375, 1440 и 3440 пикселей. Сборка сохраняет предупреждения зависимостей Zod и предупреждение о размере существующих общих пакетов; новый раздел загружается отдельным модулем.
