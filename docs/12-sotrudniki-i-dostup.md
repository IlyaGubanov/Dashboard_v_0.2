# Сотрудники: карточка, подразделения, доступ к разделам

Раздел «Пользователи и роли» (только администратор). Все изменения пишутся в журнал (`AuditService`).

## Что умеет администратор

| Действие | Где |
|---|---|
| Добавить сотрудника | «Добавить сотрудника»: ФИО, должность, подразделение, телефон, e-mail, роль в системе, вход (логин и временный пароль), галочки доступа. После создания открывается карточка на вкладке «Роли в направлениях». |
| Изменить личные данные | щелчок по ФИО → «Личные данные» |
| Назначить роли | карточка → «Роли в направлениях» (куратор / ответственный за ввод / просмотр, область ввода) |
| Видимость разделов и возможности | карточка → «Разделы и возможности»; в списке у таких сотрудников отметка «ограничен» |
| Подразделения | кнопка «Подразделения»: добавить, переименовать, убрать в архив. В карточке — выбор из списка или «+ Добавить «…»» |
| Найти | поиск по ФИО, логину, должности, подразделению, телефону; отбор по подразделению |
| Загрузить списком | колонка «Подразделение» необязательна; новое название попадает в справочник |

Телефон проверяется: цифры, пробелы, `+ ( ) - .`, не меньше 5 цифр, допускается «доб. 123».
Себя администратор не может заблокировать или лишить роли администратора.

## Разделы и возможности

Галочки только **сужают** то, что дают роли. Администратору не применяются. Изменения действуют сразу —
сервер читает их при каждом запросе; интерфейс сотрудника обновит меню при следующем открытии страницы.

| Ключ | Что скрывается | Проверка сервером |
|---|---|---|
| `overview` | «Производственная сводка» (главная → первое доступное направление) | `GET /overview` → 403 |
| `contractors` | «Подрядчики» | `/contractors` → 403 |
| `matrix`, `schedule` | вкладки «Матрица», «График работ» | `GET …/grid` → 403, если скрыты обе |
| `trackers` | «Надстройки» | `GET …/trackers` → 403 |
| `dynamics` | «Динамика» | `GET …/dynamics` → 403 |
| `remarks` | «Замечания», замечания в карточке объекта, сводке и «Моих задачах» | `…/remarks/*` → 403 |
| `people` | «Ответственные» | `GET …/people` → 403 |
| `sites`, `map`, `settings` | вкладки «Объекты», «Карта», «Устройство» | только интерфейс: те же данные нужны «Обзору» и карточке объекта |

| Возможность | Без галочки |
|---|---|
| `finance` — видеть финансы | сервер не отдаёт стоимость, КС-2, оплату, авансы, лимиты, денежные плитки и доп. поля «деньги» (`apps/api/src/kpi/finance.ts`); в листе ввода нет денежных колонок, присланные суммы не сохраняются. Вкладка «Управление» (куратор) по-прежнему показывает стоимость позиций. |
| `remarksCreate` — создавать замечания | кнопки нет, `POST …/remarks` → 403; работать с существующими замечаниями можно |
| `export` — выгрузка в Excel | нет кнопки «В Excel» (выгрузка делается в браузере, сервер тут ни при чём) |
| `audit` — журнал изменений | нет вкладки «Журнал», `GET …/audit` → 403 |

«Обзор» направления виден всегда; «Ввод данных» и «Управление» зависят от роли в направлении.

## Устройство

- Таблица `department` (название уникально, `is_archived`); у `user` — `department_id`, `hidden_sections`, `denied_features` (JSON-списки ключей).
  Миграция `20261031000000_employee_access`: новые колонки допускают NULL, существующие сотрудники видят всё, как раньше.
- Ключи и подписи — `packages/shared/src/access.ts`; `Me` и `AuthUser` несут `hiddenSections` / `deniedFeatures`.
- Сервер: `AccessService.canSee / has / assertSection / assertFeature`. Рассчитанные показатели кешируются для всех,
  поэтому деньги вырезаются из **копий** ответа.
- Интерфейс: `apps/web/src/ui/access.ts`, карточка — `pages/UserCard.tsx`, справочник — `pages/Departments.tsx`.
- API: `GET/POST /departments`, `PATCH /departments/:id`; `POST /users` и `PATCH /users/:id` принимают
  `departmentId`, `hiddenSections`, `deniedFeatures`.
